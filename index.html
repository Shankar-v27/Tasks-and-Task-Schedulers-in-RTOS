Microscopic Mechanics of a Context Switch

⏱️ 8 Min Read ⚙️ Core Architecture 🎯 GATE & Firmware Interview Priority

A context switch is the microscopic operation of stopping the currently executing task, saving its complete CPU register state onto its private stack, and restoring the register state of the next task selected by the scheduler.

The 4-Phase ARM Cortex-M Execution Sequence

On ARM Cortex-M3, M4, and M7 microcontrollers, context switching is partitioned into a collaborative hardware-software handshake to guarantee minimal interrupt latency:

Phase 1: Hardware Auto-Stacking

When the preemption exception triggers, hardware automatically pushes 8 core registers onto the task stack via the Process Stack Pointer (PSP): {R0-R3, R12, LR, PC, xPSR}.

ARM Assembly (PendSV_Handler) ; 1. Read Current Process Stack Pointer (PSP)
MRS R0, PSP
; 2. Push Software-Saved Registers R4 - R11 onto Task Stack
STMDB R0!, {R4-R11}
; 3. Save new Top-of-Stack into current TCB
LDR R1, =pxCurrentTCB
LDR R1, [R1]
STR R0, [R1] ; pxCurrentTCB->pxTopOfStack = PSP
; 4. Select Next Highest Priority Task
BL vTaskSwitchContext
; 5. Load Next Task Top-of-Stack
LDR R1, =pxCurrentTCB
LDR R1, [R1]
LDR R0, [R1] ; PSP = nextTCB->pxTopOfStack
; 6. Pop Software-Saved Registers R4 - R11
LDMIA R0!, {R4-R11}
MSR PSP, R0
; 7. Exception Return (Hardware automatically unstacks R0-xPSR)
BX LR ; LR contains EXC_RETURN (0xFFFFFFFD)

Why PendSV is Essential

If context switching were executed directly inside the SysTick timer handler, it could preempt a critical communication peripheral ISR (e.g., CAN bus or UART DMA). Configuring PendSV to the lowest interrupt priority ensures context switches are gracefully pended until all higher-priority hardware interrupts have finished!

🟢 RUNNING State

The task currently owns the microcontroller CPU core. On single-core architectures (e.g., Cortex-M4), exactly one task can reside in the Running state at any instant.

Kernel Data Pointer: pxCurrentTCB
